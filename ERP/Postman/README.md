# Excledge API Documentation (RRA / EBM + Full Backend)

Sellable, testable documentation for the Excledge backend — with a dedicated RRA/EBM surface.

## Interactive Swagger (recommended)

Start the backend, then open:

| URL | What you get |
|-----|----------------|
| `http://localhost:<PORT>/api/docs` | Docs landing page |
| `http://localhost:<PORT>/api/docs/full` | **Full** backend OpenAPI (all ~300 routes) |
| `http://localhost:<PORT>/api/docs/rra` | **RRA / EBM only** — fiscal sales, master data, stock, purchases, imports, CIS reports |
| `http://localhost:<PORT>/api/docs/openapi.json` | Full OpenAPI JSON |
| `http://localhost:<PORT>/api/docs/rra.json` | RRA-only OpenAPI JSON |

In Swagger UI: click **Authorize**, paste a JWT from `POST /api/auth/login`, then try endpoints.

## Postman collections

| File | Requests | Purpose |
|------|----------|---------|
| **`EBM-Test-Collection.json`** | **~88** | **Hands-on test kit — all EBM/RRA CIS endpoints** (ordered folders 00–11) |
| `Excledge-RRA-API-Collection.json` | ~60 | Same RRA surface, partner/demo oriented (regenerated by `docs:generate`) |
| `Excledge-API-Collection.json` | **~306** | **Entire backend API** (every route) |
| `EBM-Environment.json` | — | Shared env (`baseUrl`, login, JWT, product/purchase/import ids, TIN, …) |

### Import & run (EBM / stock / purchases / imports)

1. Postman → **Import** → `EBM-Test-Collection.json` + `EBM-Environment.json`
2. Select environment **Excledge EBM/VSDC Environment**
3. Set `loginEmail` / `loginPassword`, plus `productId`, `branchId`, `itemCd`, `itemClsCd` for your org
4. Run **`00 — Auth → Login`** (saves `jwtToken` + `organizationId`)
5. Walk folders in order:

| Folder | Coverage |
|--------|----------|
| `00 — Auth` | Login, CIS version |
| `01 — EBM Device & Outbox` | Status, initialize, outbox check/retry, Z-report |
| `02 — Org EBM Config` | Settings + fiscal identity |
| `03 — RRA Master Data` | Codes, classes, notices, TIN verify, reconcile, refund/payment maps, audit overview |
| `04 — RRA Entity Push` | Branches, customer, insurance, user, BOM composition |
| `05 — Stock In/Out & Master` | Queue status, sync, stock-moves, ledger IN/OUT/adjust, transfers |
| `06 — B2B Purchases` | Sync, list, **confirm (02 + stock master)**, **reject (04)** |
| `07 — Import Declarations` | Sync, list (**includes `spplrNm` supplier**), approve, reject |
| `08 — Fiscal Sales` | Create, receipt, PDF, convert, refund, void, reprint |
| `09 — Fiscal Reports` | Daily X/Z, PLU, electronic journal, purchases report |
| `10 — Sync Triggers` | Product / customer / BOM / production → RRA |
| `11 — Direct VSDC WAR` | Raw sandbox calls (debug only) |

List Purchases / Imports / Outbox / Sales scripts auto-save `purchaseId`, `importId`, `outboxId`, `saleId`.

### Full backend (all ~306 endpoints)

Import `Excledge-API-Collection.json` + the same environment. Use when you need non-EBM modules (PO, suppliers, shifts, subscriptions, …).

## Regenerate docs after route changes

```bash
cd Backend
npm run docs:generate
```

This refreshes:

- `Backend/src/docs/openapi.json`
- `Backend/src/docs/openapi-rra.json`
- `Backend/src/docs/route-catalog.json`
- `Postman/Excledge-API-Collection.json`
- `Postman/Excledge-RRA-API-Collection.json`
- `Backend/postman_collection.json`

> Note: `EBM-Test-Collection.json` is the curated hands-on suite — it is **not** overwritten by `docs:generate`.

## Prerequisites for live RRA tests

1. Backend on your configured `PORT` (Postman default `4500`)
2. VSDC sandbox WAR on `8085` (for folder `11 — Direct VSDC`)
3. Org with EBM enabled (`featureFlags.ebmIntegrationEnabled`) and device initialized
