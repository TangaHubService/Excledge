1. VSDC service   1.1. Introduction  Virtual Sales Data Controller known as VSDC is a communication module for private CIS/ERP applications to send/receive various data (sales, purchase transaction data, receipts, etc.) to and from the RRA EBM server in other word it is like a bridge system Between RRA EBM systems and private CIS/ERP.  1.2. Environment  VSDC has two types; Production and Test.  Type Description Remark Production VSDC Server CIS application utilizes a Production VSDC to send and receive data to and from the RRA EBM API production server.   Test VSDC During development, the test application can send and receive test data to and from the RRA EBM API test server using a Test VSDC.   
 The following is a Test VSDC technical information Title Contents Remark Supported Software Language All / Web services  Distributed Package  WAR  API architectural style of web service REST  Supported web server  Tomcat, Jetty, Apache HHTP Server,  Interface data format JSON  O/S Windows 10+, Linux, Unix  EBM 2.1 API Server Address (Production)   EBM 2.1 API Server Address (Test)   VSDC Request form (Production)   VSDC Request form (Test)

2. Technical outline  2.1. The application process to use VSDC   To use VSDC, a taxpayer must apply for VSDC service and get approval from RRA.  
  After the approval of VSDC, a WAR file is deployed in your local webserver through its web services a taxpayer can call Initialization service to start activation. When a taxpayer calls the initialization Service URL of VSDC with TIN, branch office, and equipment information as request body, VSDC will begin verification of the device and receive and save keys from the RRA EBM API server. 
  2.2. VSDC running process and main configurations  There are several technical policies that VSDC users have to follow.  1. To use VSDC a WAR file is deployed on your local webserver and need to be up and running locally. 2. Sending/Receiving data to and from EBM 2.1 API Server will be done by calling Methods of VSDC web services from a VSDC WAR deployed on your local webserver 3. To retrieve the latest data from EBM 2.1 API server, VSDC shall send the ‘Date and Time’ on which the kind of data was finally received from the EBM 2.1 API server. So, the ‘Date and Time’ of final request should be managed by CIS, and once successfully retrieved, CIS shall update the latest ‘Date and Time’ to the related data for the next update. 4. If there is no internet connection for 24 hours after VSDC issues a receipt signature and an internal data, VSDC stops issuing a receipt number.

3. VSDC business process  3.1. VSDC functions  The services provided in this VSDC are grouped by its purpose into eight (8) categories. The below briefly introduces the purpose of each category.  1. Data initialization (Send only) a. For a device authentication (VSDC), registration and approval of equipment must be completed.  2. Code data (Get only) a. Methods of this category are used to receive necessary standard codes and data from the EBM 2.1 API Server, which is the basis of generating invoice data. To send Invoice data to the EBM 2.1 API server, the consistency of the data is essential.  b. The standard codes and data are including; item classification code for managing item, location code, and package, weight code, TIN list and notice from RRA. For more information, check code definition chapter. 3. Branch information (Send only) a. Methods of this category are to send customer list of head and branch offices and user accounts of branch offices.  b. This category has a method which requests branch codes to be used later while sending stock from main branch to branch offices. 4. Item information (Send only) a. Methods of this category are to send registered item and item composition information in a CIS application.  b. In case you want to recover your items, you can receive them through EBM2.1 API server. 5. Imported item (Get and Send) a. Methods of this category are to receive data of imported items which is declared by the TIN of CIS application owner and to send confirmation of the received imported items.  b. The imported items data are retrieved from RRA customs system and data can be used for stock adjustment. 6. Sales management (Send only) a. Methods of this category are to send data of sales transaction and sales Invoice to EBM server. b. Sales transaction data is composed of sales contract such as Customer TIN, Customer Name, Sales Type Code, Receipt Type Code, Payment Type Code, Invoice Status Code, Validated Date, Sale Date, Stock Released Date, Cancel Requested Date, Canceled Date Refunded Date and etc. c. Sales Invoice data is composed of Invoice information such as Invoice Number, Current Receipt Number, Total Receipt Number, Customer TIN, Customer Mobile Number, Receipt Published Date, Internal Data, Receipt Signature and etc. 7. Purchase information (Get and Send) a. Methods of this category are to request data of purchase transaction of the TIN of CIS application owner to EBM server and send confirmation of the transaction. b. When a seller registers sales transaction and Invoice data to EBM server, buyer can request such data for purchase confirmation and stock adjustment purpose.
