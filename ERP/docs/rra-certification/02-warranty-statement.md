**1.3 "VSDC" or "Virtual Sales Data Controller"** means the software module approved by the Rwanda Revenue Authority that communicates with a Certified Invoicing System to receive transaction data, apply a cryptographic signature to each transaction, generate a certified receipt, and transmit the signed transaction data to the RRA Authority Server. **1.4 "RRA"** means the Rwanda Revenue Authority, a government body established under the Laws of the Republic of Rwanda, responsible for the assessment and collection of taxes, including Value Added Tax, and for the administration of the EBM/CIS programme requiring certified invoicing by qualifying taxpayers.

Each Branch in the Excledge system stores its MRC in the `ebmSerialNo` field.

**1.6 "Receipt"** means any of the following document types generated by the Software in response to a sales transaction: NS (Normal Sale), NR (Normal Refund), CS (Copy Sale), CR (Copy Refund), TS (Training Sale), TR (Training Refund), or PS (Proforma Sale), as defined in Section 5 of the RRA CIS/VSDC Technical Specification.

**1.7 "Certified Receipt"** means a Receipt of type NS or NR that has been cryptographically signed by the VSDC, contains a valid SDC INFORMATION block (including VSDC date and time, SDC ID, receipt counter in A/B RT format, internal data value, receipt signature, and QR code), and has been successfully transmitted to the RRA Authority Server via the VSDC. ## SECTION 2: WARRANTY COVERAGE

### 2.1 Functional Warranty — Duration: 12 (Twelve) Months from Installation Date

[COMPANY LEGAL NAME] warrants that the Software, when installed, configured, and operated in accordance with the documentation provided, will perform all functions specified in the RRA CIS/VSDC Technical Specification Version 1.0 (March 2018) for which it has been designed. The following twenty (20) functions are specifically warranted:

**Warranted Function 1 — Normal Sale Receipt (NS)**
The Software shall generate a valid Normal Sale (NS) Certified Receipt for every completed sale transaction, containing all mandatory fields required by the RRA specification, including the correct VAT calculation, the SDC INFORMATION block, and a valid QR code in the format `ddmmyyyy#hhmmss#sdc#rcpt#data#sig` as returned by the VSDC.

**Warranted Function 2 — Normal Refund Receipt (NR)**
The Software shall generate a valid Normal Refund (NR) receipt for any refund of a previously certified NS receipt, containing a mandatory reference to the original NS receipt number and all fields required by the specification. Each NS receipt may be refunded at most once (cancel-once rule enforced).

**Warranted Function 3 — Copy Sale Receipt (CS)**
The Software shall generate a Copy Sale (CS) receipt that is a faithful reprint of a previously issued NS receipt, clearly marked as a copy, with all original SDC INFORMATION fields reproduced identically.

**Warranted Function 4 — Copy Refund Receipt (CR)**
The Software shall generate a Copy Refund (CR) receipt that is a faithful reprint of a previously issued NR receipt, clearly marked as a copy, with all original SDC INFORMATION fields reproduced identically.

**Warranted Function 5 — Training Sale and Refund Receipts (TS/TR)**
When the Organisation is placed in training mode (`Organization.trainingMode = true`), the Software shall generate only TS (Training Sale) and TR (Training Refund) receipts, which shall be clearly watermarked as training documents and shall not be submitted to the VSDC or the RRA Authority Server.

**Warranted Function 6 — VSDC Communication Timeout Compliance**
Every VSDC API call made by the Software shall enforce the 1,000-millisecond (one second) timeout as required by CIS specification Section 24.2.1. The configuration value `EBM_REQUEST_TIMEOUT_MS=1000` shall be respected at all times and shall not be overridden or exceeded in any production deployment.

**Warranted Function 7 — SDC INFORMATION Block on Every Certified Receipt**
Every Certified Receipt generated by the Software shall include the complete SDC INFORMATION block as returned by the VSDC, comprising: the VSDC-assigned date and time, the SDC ID, the receipt counter in A/B RT format, the internal data value, and the receipt signature displayed with a dash character after every four characters.

**Warranted Function 8 — QR Code Generation in Mandated Format**
The Software shall include on every Certified Receipt a machine-readable QR code encoding the string in the exact format `ddmmyyyy#hhmmss#sdc#rcpt#data#sig`, using the values returned by the VSDC for the respective transaction.

**Warranted Function 9 — Receipt Signature Display**
The Software shall display the receipt signature on every Certified Receipt with a dash separator inserted after every four characters of the signature string, in accordance with the RRA specification for signature formatting.

**Warranted Function 10 — VAT Calculation by Tax Code**
The Software shall correctly calculate VAT for each transaction line item based on the RRA tax code assigned to the item, using the following rates: Tax Code A (exempt, 0%), Tax Code B (standard rate, 18%), Tax Code C (zero-rated, 0%), Tax Code D (as specified), and Tax Code E (as specified). The receipt shall print the taxable amount and VAT amount for each tax code where the value is greater than zero.

**Warranted Function 11 — Sequential Receipt Numbering**
The Software shall maintain an independent, gapless sequential receipt counter per Branch per receipt type, stored in the `BranchReceiptCounter` table. Receipt numbers shall be displayed in the A/B RT format (e.g. `168/258 NS`) where A is the type-specific counter, B is the cumulative branch counter, and RT is the receipt type label. No gaps, duplications, or resets shall occur except as part of a legitimate Z Report end-of-day closure.

**Warranted Function 12 — X Report Generation**
The Software shall generate an X Report (interim daily summary report) on demand for any branch at any time during the business day, covering all transactions from the last Z Report closure to the current time, including all required fields per specification Section 18, without resetting any counters.

**Warranted Function 13 — Z Report Generation**
The Software shall generate a Z Report (end-of-day closing report) for any branch at the end of the business day, covering all transactions since the last Z Report, including all required fields per specification Section 19. Z Reports shall be electronically submitted to the VSDC. Once generated, a Z Report record shall be permanently immutable and the branch daily receipt counter shall be reset.

**Warranted Function 14 — Electronic Journal (EJ_DATA)**
The Software shall generate and transmit a complete EJ_DATA payload to the VSDC for every NS and NR transaction, in the format specified in CIS specification Sections 6.5 and 24.7.7, via the `electronic-journal.service.ts` module.

**Warranted Function 15 — Stock Gate Enforcement**
The Software shall prevent the completion of any sale transaction involving a physical stock item (`ItemType.PRODUCT`) where the requested quantity exceeds the available stock at the selling branch. Service items (`ItemType.SERVICE`) are exempt from this check. The stock gate shall be enforced atomically within the sale transaction to prevent overselling.

**Warranted Function 16 — Cancel-Once Enforcement**
The Software shall enforce the rule that each NS Certified Receipt may be refunded (generating an NR receipt) at most once. Any attempt to generate a second NR receipt referencing the same original NS receipt shall be rejected by the system with an appropriate error message.

**Warranted Function 17 — Receipt Immutability**
Once a Certified Receipt has been issued and the corresponding VSDC response has been recorded, the receipt data shall be permanently immutable within the Software's database. No user, including system administrators, shall be able to modify the receipt data, the SDC INFORMATION fields, the VAT amounts, or any other field of an issued receipt. Refunds shall be processed by creating a new NR receipt, not by modifying the original NS receipt.

**Warranted Function 18 — Training Mode**
The Software shall implement a training mode controlled by the `Organization.trainingMode` boolean field. When training mode is active, all receipts shall be of type TS or TR, clearly watermarked, and no data shall be submitted to the VSDC or the RRA Authority Server. The mode shall be toggleable only by users with the appropriate administrative permission level.

**Warranted Function 19 — MRC Display**
The Software shall display the Machine Registration Code (MRC) in the format `BBBCCNNNNNN` on all relevant receipt outputs and in the branch settings interface, using the value stored in the `Branch.ebmSerialNo` field as registered with the RRA.

**Warranted Function 20 — Offline Queue and Guaranteed VSDC Delivery**
The Software shall implement the transactional outbox pattern using the `EbmOutbox` table to guarantee that every completed sale transaction is submitted to the VSDC, even in the event of temporary network interruptions or VSDC unavailability. The outbox worker (`ebm-outbox.job.ts`) shall retry failed submissions with exponential backoff. No transaction shall be permanently lost due to a temporary VSDC communication failure; any transaction that cannot be delivered within the maximum retry period shall be escalated to `DEAD_LETTER` status and flagged for manual review.
